# Mac Utility — Design

I need your approval on this doc, plus answers to the open questions at the bottom, before I start building.

## Shape

- Menu bar only app (`LSUIElement`, no Dock icon). SwiftUI `MenuBarExtra`, with AppKit for the panels, event taps and Accessibility calls.
- Target macOS 14+. Swift 6, Xcode project generated by XcodeGen so the repo stays diffable.
- Not sandboxed. Event taps, synthetic paste and moving other apps' windows all need Accessibility, and the sandbox blocks that. Distribute with Developer ID signing and notarization, not the App Store.
- Permissions: Accessibility (window moves, paste, keyboard block) and Input Monitoring (keyboard block). A first-run screen checks both and links to the right System Settings pane.
- Launch at login via `SMAppService.mainApp`.
- Global hotkeys via `KeyboardShortcuts` (sindresorhus). User can rebind them in Settings.

Menu bar menu:

```
Keyboard Cleaning Mode      ⌃⌥⌘K
Clipboard History…          ⇧⌘V
Move Window to Next Display ⌃⌘→
Move Window to Prev Display ⌃⌘←
───────────────
Settings…   Quit
```

Code layout:

```
App/            MacUtilityApp, AppDelegate, MenuBar
Core/           Permissions, Hotkeys, Settings (UserDefaults via @AppStorage)
Features/
  KeyboardClean/   KeyboardBlocker (CGEventTap), CleaningOverlay
  Clipboard/       PasteboardWatcher, ClipStore, HistoryPanel, Paster
  Windows/         WindowMover, ScreenGeometry
```

Each feature is a separate service the app owns. Features don't depend on each other.

## 1. Keyboard cleaning mode

- Turning it on installs a `CGEventTap` at the session level. It swallows `keyDown`, `keyUp`, `flagsChanged` and `NSSystemDefined` (media, brightness and volume keys).
- A full-screen overlay on every display shows "Keyboard locked for cleaning", a countdown and an Unlock button. The mouse/trackpad stays live, so clicking Unlock is the exit.
- Safety net: it unlocks automatically after 60s (configurable). If the tap gets disabled by the system (`tapDisabledByTimeout`), it re-enables itself.
- Limits: the power/Touch ID button and the Globe key's hardware functions can't be blocked from user space. Touching the trackpad still works by design.

## 2. Clipboard history

The goal is to open instantly. The panel is created once and kept warm, with history in memory and persisted in the background.

Capture:
- Poll `NSPasteboard.general.changeCount` every 300 ms. macOS has no change notification, so every clipboard manager does this. The cost is negligible.
- Stored types: plain text, RTF/HTML (with a plain text fallback), images (PNG, plus a thumbnail), file URLs, and the source app's bundle ID and icon.
- Skip anything marked `org.nspasteboard.ConcealedType` or `TransientType` (password managers set these), plus a user list of excluded apps (1Password and Keychain Access by default).
- Duplicates move the existing item to the top instead of adding a copy.

Storage:
- SQLite via GRDB in `~/Library/Application Support/MacUtility/`. Image blobs go in files next to it. FTS5 index for search.
- Retention: last 1,000 items or 30 days, whichever comes first (configurable). Pinned items never expire.

UI (Paste-style):
- `⇧⌘V` opens a non-activating `NSPanel` as a bottom strip of cards on the active display, so focus stays in the target app.
- Type to search right away. ←/→ to move, Return to paste, ⌘1–9 for quick paste, ⌘D to favorite (favorites are never pruned), Tab to show only favorites, ⌫ to delete, Esc to close.
- Each card shows a content preview, the source app icon and how long ago it was copied.

Paste:
- Write the item back to the pasteboard, close the panel, then post a synthetic ⌘V with `CGEvent`. ⇧Return pastes as plain text.
- Our own write is tagged with a marker type so the watcher doesn't re-record it.

Risk: Apple has been adding privacy prompts for programmatic pasteboard reads. If macOS starts prompting on every read, the user has to grant the app "always allow" once. I'll check how this behaves on your OS version first.

## 3. Window manager — move between displays

- `⌃⌘→` and `⌃⌘←` move the frontmost window to the next or previous display, ordered left to right by screen position, wrapping around.
- Get the focused window with `AXUIElementCreateApplication(frontmostPID)` and `kAXFocusedWindowAttribute`, then read `kAXPosition`/`kAXSize`.
- Center the window in the target screen's visible frame (excluding menu bar and Dock). If it's bigger than that, scale it down to fit.
- AX uses top-left origin coordinates and `NSScreen` uses bottom-left. One helper converts between them.
- Order of operations: set size, then position, then size again. That's the known workaround for apps that clamp size to the current screen.
- Skip native full-screen windows (moving them via AX doesn't work reliably) and show a short HUD instead.

## 4. Focus — one display, one stage

Previews: https://claude.ai/artifact/EZ8EqPgVFXvK9famhZkgFa (the Switcher and Replace boards are interactive). Built on the `focus-window-manager` branch; "Status" at the end of this section says what isn't done or verified yet.

The screen shows one small group of windows at a time. Everything else is parked out of sight and comes back with one keystroke. It's built for a single display, laptop or desktop. The `⌃⌘←`/`⌃⌘→` display moves from section 3 keep working unchanged.

### Model

- **Stage:** the visible frame of the managed display, minus a gap on every side (12 pt by default, 0–40 pt in Settings), the same gap as between two windows. Only the current set is on it.
- **Set:** up to 2 windows, numbered 1–9. A set is named after its first window's app, and has a layout. The stage shows exactly one set at a time.
- **Layouts:**
  - One window: it fills the stage, up to a width cap, then centers.
  - Two windows: either split side by side, or stacked, where only the focused one shows at full stage size and the other is parked behind it.
  - Split ratio: drag the gap to change it. It snaps to 1/3, 1/2 and 2/3. The default is 1/2.
- **Width cap:** a lone window stops at 1440 pt wide and centers. On the laptop this never kicks in, but on the 1920 Dell it does. Split sets use the full width. The cap is configurable in Settings.
- **Floating:** dialogs, sheets, panels, windows that can't be resized, and apps on a float list are never tiled or counted. They stay where the app puts them. `⌃B` `\` toggles floating for the focused window.
- **Unmanaged:** minimized windows, native full-screen windows, windows on other displays and windows on other macOS Spaces. When a window becomes managed again, it rejoins the set it was in.

### Rules

- **New window:** it joins the current set if the set has room. Otherwise it opens a new set (the lowest free number), takes you there, and the HUD says why.
- **Closing a window:** if one window is left, it fills the stage. If the set becomes empty, it keeps its number and you stay on an empty stage. `⌃B` `⇥` takes you back.
- **Sending a window to a set (`⌃B` `⇧N`):** if set N has room, the window joins it. If set N is full, the window swaps places with set N's unfocused window. You go with it to set N, with the same slide as a switch.
- **Replace (`⌃B` `R`):** puts a window from another set, or a new app, into the focused window's place.
  - A window from another set trades places with the focused window.
  - A new app pushes the focused window into a new set.
  - The HUD offers Undo for 5 s.
- **Quitting an app** takes its windows out of their sets. When the app relaunches, its windows go back to their last set, matched by bundle ID plus window title, or by bundle ID alone for apps with one window.
- **Pinning:** an app can be pinned to a set (Settings, or the switcher's context menu). Its new windows go there instead of following the new-window rule.
- **Previous set:** `⌃B` `⇥` goes back to the last set you were in. Doing it again comes back, like i3.

### Shortcuts: a leader key, like tmux

- **Leader:** press `⌃B` (like tmux's prefix), let go, then press one command key, e.g. `⌃B` `3` goes to set 3. It's the only global hotkey Focus registers, and it can be rebound in Settings.
- **Key guide:** if no second key comes within 500 ms, a small key guide appears at the bottom of the screen. The shelf appears at the same time, since a pause usually means you're looking for something. The leader stays armed until you press a key, press `Esc` or click elsewhere.
- **Arrows repeat:** after an arrow, the leader stays armed for 600 ms so more arrows work without pressing it again, like tmux's repeat flag.
- **Passthrough:** pressing `⌃B` twice sends `⌃B` to the app. That's how tmux's own prefix and Emacs-style "back one character" in text fields still work.
- **Unknown keys:** an unbound key closes the guide and does nothing. It never reaches the app.

| After `⌃B` | Action |
| --- | --- |
| `1`–`9` | Go to set |
| `⇧1`–`9` | Send focused window to set |
| `⇥` | Previous set |
| `v` | Split side by side (vim `Ctrl-w v`): the window takes the left half now, a picker opens in the empty right pane. With two windows, turn the split side by side |
| `s` | Same, top and bottom (vim `Ctrl-w s`) |
| `t` | Flip the split between side by side and top and bottom; a stacked set comes back split |
| `o` | Only (vim `Ctrl-w o`): keep the focused window, move the other to a new set |
| `h` `j` `k` `l` / arrows | Focus the pane in that direction |
| `⇧h` `⇧j` `⇧k` `⇧l` / `⇧`arrows | Swap the two windows |
| `↩` | Split ⇄ stacked |
| `Space` | Switcher |
| `R` | Replace focused window |
| `F` | Zoom focused window to the full stage, no width cap; again to restore |
| `\` | Float / unfloat |
| `⌃B` | Send `⌃B` to the app |
| `Esc` | Cancel |

`⌃⌘←`/`⌃⌘→` (move window to the other display) stay direct hotkeys, unchanged. A three-finger swipe up opens the switcher and a swipe down closes it (three or four fingers, or off, in Settings). macOS has no public API for trackpad gestures, so this reads raw touches through the private MultitouchSupport framework, loaded at runtime like MiddleClick and BetterTouchTool do; if it's missing, the swipe does nothing. macOS's own Mission Control swipe has to be off, or both open. `⌃↑` opens the switcher directly while Focus runs, standing in for Mission Control: parked windows sit in a corner, so Mission Control shows them small and scattered. macOS keeps `⌃↑` for Mission Control until it's switched off in Keyboard Shortcuts, and "Group windows by application" makes Mission Control itself readable again.

How it works:
- The leader is a `KeyboardShortcuts` hotkey, like the others.
- Pressing it opens a non-activating key panel that takes keyboard focus, like the clipboard panel. The panel is invisible until the 500 ms guide delay.
- The panel reads the next key, runs the command, closes and hands focus back to the window you were in. No event tap and no new permission.
- For passthrough, Focus disables the hotkey, posts the leader keystroke with `CGEvent`, then re-enables it. The Carbon hotkey would otherwise catch the synthetic press.

### UI

- **Menu bar:** the existing item gains the numbers of the sets that have windows, with the current one filled in. Clicking it opens the switcher.
- **HUD:** doesn't show for plain set switches; the stage and the menu bar numbers already say where you are. It shows when a new window opens a new set because yours was full, when you send a window to another set, and after Replace. It shows the set number, name, apps and the occupied sets, then fades after 1.2 s. Built on the existing `HUD`.
- **Shelf:** a strip of cards for the other sets at the left edge. It appears when the pointer rests at the edge for 150 ms or when the leader's key guide appears. Click a card to go there.
- **Switcher:** a full-screen 3×3 grid in which each set's position matches its number.
  - No search. `h` `j` `k` `l` or the arrows move through the grid, stopping at its edges; the pointer selects too. `Return` goes, `1`–`9` jump straight to a set (empty ones included), `Esc` closes.
  - Opening dims and blurs the stage and springs the grid in from 96%; closing eases out in 0.14 s.
  - It opens on the previous set, so `⌃B` `Space` `Return` works like ⌘Tab.
- **Replace picker:** sits over the window being replaced, which dims and gets an accent outline, with a card listing windows in other sets (each with its set badge), then running apps that have no window in any set. No search: `j` `k` or the arrows move, `Return` replaces, `Esc` cancels. An app that isn't running has to be opened the normal way; its window then follows the new-window rule.
  - `/` turns the list into a search field: it filters the windows and lists matching installed apps (`/Applications`, `/System/Applications` and its Utilities, `~/Applications`), running or not. Arrows move while typing; Esc clears, then leaves search. Choosing an app that isn't running opens it; its first window takes the spot.
  - On an empty set, `⌃B` `r`, `v` and `s` open the picker over the whole stage in search mode ("Open on this set"). A window from another set moves here; an app's existing window moves here, otherwise the app opens and its window joins this set by the new-window rule.
- **Panels:** all of them are non-activating `NSPanel`s, so focus stays in the app you were using, the same as the clipboard panel.
- **Motion:** kept as simple as possible. Settings → Focus → Switch animation offers Fade (default) or None.
  - Fade: freeze the screen below the menu bar as it is, move and activate the real windows underneath, wait 80 ms for the apps to redraw, then fade the frozen picture out over 0.14 s. Nothing on screen is ever a picture of where a window is going, so nothing can disagree with the real screen when it goes away.
  - Focus's panels set `animationBehavior = .none`. macOS otherwise gives a newly shown panel its own "pop in": it scaled the frozen picture down about 1.5% and back over 300 ms, which read as the screen shrinking on every switch.
  - Known leftover: ScreenCaptureKit draws the active window's shadow a little lighter than the screen does, so the shadow edge softens faintly while the picture is up. No position or size changes.
  - None: windows just move. Measured on recordings, each switch is a single-frame cut with nothing in between.
  - Sending a window with `⌃B` `⇧N` uses the same fade.
  - A Spaces-style slide was built and dropped: every way of faking the incoming stage (composed window captures, captures of the new stage under the cover) left a visible snap, shrink or flick at the end, and a hidden implicit animation made it jump back mid-slide.
  - With Reduce Motion on, or without Screen Recording, windows jump without animation.
- **Memory:** about 30 MB at rest. Card thumbnails are kept at most 600 px wide; full-resolution captures live only for the length of a slide, and the wallpaper capture is cached at 1×. A crossfade was tried first; blending two apps in the same frame looked like one window being squeezed into another. If the second capture fails, the cover just fades. With Reduce Motion on, or without Screen Recording, windows jump without animation.

### Implementation

- **Code:** everything is under `Features/Windows/Focus/`:
  - `StageState`: sets and rules, pure and testable.
  - `StageLayout`: frames and parking corners, pure.
  - `WindowRegistry`: tracks windows.
  - `FocusController`: placement, parking, events and commands.
  - `FocusStore`: the state file, crash recovery and the Stage Manager check.
  - `FocusPanels`: leader key, key guide, HUD.
  - `FocusPickers`: switcher, Replace picker, shelf.
  - `StageMotion`: crossfade and thumbnails.
  - The AX helpers moved out of `WindowMover` into `AXUIElement+Helpers.swift`, so both share them.
- **Tracking:**
  - One `AXObserver` per running app, for window created, destroyed, focused, minimized, deminiaturized, moved and resized.
  - `NSWorkspace` notifications for app launch, terminate, activate, hide and unhide.
  - Window identity comes from `_AXUIElementGetWindow`, which is private but has been stable for years and is used by every macOS window manager. A window without an ID is left unmanaged. Destroyed windows no longer answer, so those are matched by AX element.
- **Parking:** a parked window keeps its size and moves to the bottom-right corner of the managed display, with a 1 pt sliver left on screen, because macOS won't let a window go fully off-screen. This is AeroSpace's approach and needs only Accessibility. Real Spaces would need SIP disabled, so they're out.
- **Recovery:** this is the main risk, and it ships in step 1.
  - Every park writes the window's last on-stage frame to `~/Library/Application Support/MacUtility/focus-state.json`.
  - When the app quits, or Focus is switched off, every parked window is brought back.
  - At launch, if the state file shows an unclean exit, every parked window is brought back before anything else runs.
- **Thumbnails:** each time the switcher or shelf opens, every managed window is captured on its own through ScreenCaptureKit (`desktopIndependentWindow`), parked ones included, at up to 640 pt wide. Cards fill in as each capture lands. Crossfade stills are kept as a fallback. This reuses the Screen Recording permission from screen capture; without it, cards show app icons.
- **Managed display:** the one with the menu bar, `NSScreen.screens[0]`. A window moved onto it with `⌃⌘←`/`→` follows the new-window rule. A window moved off it leaves its set.
- **Stage Manager:** Focus reads `com.apple.WindowManager GloballyEnabled`. If Stage Manager is on, Focus won't start. It shows a sheet with a button that opens Desktop & Dock settings. It's on on this Mac right now.
- **Spaces:** Focus assumes one Space per display. Windows on other Spaces aren't managed, and Settings recommends a single Space.
- **Feature flag:** a new `Feature.focus`, off by default and turned on from Settings because it takes over every window. It's separate from `Feature.windowManager`, which keeps the display moves.
- **Tests:** `MacUtilityTests` (Swift Testing) compiles only `StageState` and `StageLayout`, so it runs without launching the app. 27 tests cover layout frames and the width cap, the new-window rule, send to a full set, Replace swaps and Undo, closes, adoption, ratio snapping and parking corners.
- **Leaving a parking corner:** an app that quits while its window is parked reopens it in the corner. Focus treats a window that is off every display but touches the managed one as belonging to it.
